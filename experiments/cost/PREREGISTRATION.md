# Computational Cost Analysis：预注册协议

冻结日期：2026-10-23  
状态：待服务器重新开机后执行  
适用范围：CAIL2020-SFZY-clean 上五种具有可审计完整实现的方法

## 1. 研究目的与结论边界

本实验只回答两个计算成本问题：

1. 从共同的已切句 JSONL 出发，完成方法专属准备、训练和 942 篇开发集预测需要多少时间？
2. 模型训练完成后，从同一批已切句开发文档出发，完成必要表示计算、句子评分、预算约束选择和预测写盘需要多少时间？

结果作为补充性的计算成本分析，不构成论文核心创新，也不支持“整体效率最优”“最佳效率—效果权衡”或相对全部基线领先的主张。

覆盖方法：LegalFactAware、SSE、SENDE、MemSum、TermDiffuSum。Agarwal-ST、Gist、EUR-Lex-Sum LexRank、CivilSum LED-tail 和 Budget Recipe 因缺少同口径、可审计的完整本地计时流程，不进入本次效率表，但继续保留在效果主表中。

## 2. 冻结数据与效果关联

- 共同输入：冻结的 CAIL2020-SFZY-clean 已切句 JSONL。
- 训练集：7,495 篇；开发集：942 篇。
- 固定开发集文档 ID、文件顺序和 SHA-256；任何一次输出必须覆盖相同 942 篇。
- 固定每种方法的代码快照、配置、随机种子、训练轮数、检查点选择规则、输入上限、450 字预算、最大句数和完整句处理规则。
- 每次完整运行结束后，在计时区间之外使用统一评价器计算 ROUGE、预算违规数和空输出数；确认计时模型与论文所报告的相应冻结配置一致。
- 不允许为缩短时间而减少 epoch、修改批大小、修改解码或复用旧模型后继续沿用原有效果分数。

## 3. 实验 A：完整流水线成本

### 3.1 起止点

- 起点：共同的已切句 JSONL 和预先下载的基础模型权重已经存在。
- 计入：方法专属监督/Oracle 构造、预处理、训练语料表示、训练、训练流程必需的开发集检查点评估与选择、942 篇开发集预算约束预测及预测文件写入。
- 终点：942 条合法预测写入独立输出目录并完成完整性核验。
- 排除：数据下载、公共清洗与划分、软件安装、基础模型下载、计时结束后的统一 ROUGE 汇总。

### 3.2 重复和隔离

- 每种方法独立完整运行 3 次，使用同一冻结随机种子；衡量运行时间重复性，不据此声称跨种子效果稳定。
- 每次使用新进程和独立输出目录：`pipeline/<method>/run_{1,2,3}`。
- 每次运行前确认不存在该方法先前生成的 Oracle、句向量、词表、适配数据、训练模型、开发集预测或方法专属缓存。
- 公共 JSONL、软件环境和预下载基础模型权重允许复用。
- 服务器专用于本实验；按顺序独占 GPU/CPU，不并发运行其他训练任务。
- 固定并保存交错运行顺序，避免某一方法总处于相同位置。预定顺序：
  - Round 1：SSE → LegalFactAware → SENDE → MemSum → TermDiffuSum
  - Round 2：TermDiffuSum → MemSum → SENDE → LegalFactAware → SSE
  - Round 3：LegalFactAware → TermDiffuSum → SSE → MemSum → SENDE

### 3.3 报告

- 每次原始外层 wall-clock 时间。
- 三次平均值、样本标准差、最小值和最大值。
- 方法内部阶段时间与未分配开销：`外层总时间 - 已分解阶段之和`。
- 不对五种方法的时间差进行显著性检验；三次重复主要用于描述运行波动。

## 4. 实验 B：统一起点推理成本

### 4.1 主指标起点

模型及仅与训练有关的固定资源已加载。计时从读取冻结的已切句开发集文档开始，覆盖：

1. 方法所需的开发集预处理和分词；
2. 开发集句子表示或编码；
3. 句子评分；
4. 冗余控制和预算约束完整句选择；
5. 942 条预测写盘。

禁止复用开发集句向量、已分词开发输入、扩散中间状态或预测缓存。SENDE 必须在每次正式测量中重新编码开发集句子，不能直接读取预编码矩阵。

### 4.2 加载、预热和重复

- 模型与固定训练资源加载耗时单独记录，不计入主批处理推理时间。
- 加载完成后使用不属于 942 篇正式开发集的独立样本预热一次。
- 正式处理 942 篇开发集 5 次，每次重建所有与开发集有关的表示并写入独立预测文件。
- GPU 计时在开始前和结束写盘前执行正确同步。
- 汇报五次平均值±样本标准差；另列模型加载时间。
- `总时间 / 942`只称为平均每篇处理时间，不称为单请求延迟。

### 4.3 阶段分解

- input/read + preprocessing
- representation/encoding
- scoring/model forward
- constrained decoding
- serialization

原有“缓存输入后的模型推理”仅作为附录阶段记录，不进入统一起点主表。

## 5. 环境与追溯记录

每次运行必须保存：

- 日期、开始/结束时间和时区；服务器/实例标识。
- CPU 型号、物理核/逻辑线程数、内存、GPU 型号和驱动。
- CUDA、cuDNN、Python、PyTorch、Transformers及关键库版本。
- CPU线程环境变量、数据加载 worker 数、batch size、计算精度和设备。
- 完整命令、配置文件、随机种子、代码文件 SHA-256。
- 输入数据、模型检查点和预测文件 SHA-256。
- 外层总时间、各阶段时间、未分配开销、峰值 CPU RSS、峰值 GPU 显存和平均/峰值 GPU 利用率。
- 输出数量、文档 ID 顺序、预算违规、硬截断、空输出和失败数量。
- 运行前后磁盘空间以及是否存在其他 GPU/CPU 任务。

## 7. 完成判据

- 15 次完整流水线运行全部退出码为 0，并各产生 942 条预测。
- 25 次统一起点推理运行全部退出码为 0，并各产生 942 条预测。
- 无预算违规、无硬截断、无空输出；如发生异常，保留失败日志并重新运行，不覆盖原记录。
- 计时模型配置与对应效果配置一致；计时区间外统一重评结果可追溯。
- 正文只报告均值±标准差和主要成本观察；完整阶段、环境、每次记录及异常日志进入附录或补充材料。

## 8. 预计资源

依据 2026-10-22 的单次完整测量，15 次完整流水线串行理论时间约 16.7 小时。统一起点推理受 TermDiffuSum 扩散解码影响，预计约 2–3 小时。加上清理、完整性检查和输出评价，服务器应连续预留约 20–22 小时，并保证不少于 8 GB 的安全可用磁盘空间。
