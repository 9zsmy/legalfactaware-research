# 补充实验代码讲解稿

## 30 秒开场

这套代码不是为了重新优化测试集结果，而是针对审稿人提出的四个机制混杂，在冻结开发集上做受控实验。主脚本负责生成对照、统一解码和统计检验；跟进脚本只分析已经生成的结果。两者都没有测试集参数。

## 第一部分：如何保证没有重新调测试集（约 1 分钟）

打开 `run_reviewer_controls.py` 顶部：

1. `EXPECTED` 固定训练集、开发集、Oracle 标签、向量器和分类器的 SHA-256。
2. `require()` 在运行前逐一校验文件。
3. `parse_args()` 中不存在 test 参数。
4. `SEED=42`，LR 的 solver、class weight、最大迭代次数均固定。

一句话解释：**先锁输入，再做机制对照，不能根据测试结果回头改实验。**

## 第二部分：标签数量匹配对照（约 2 分钟）

重点展示 `build_training()`：

```text
每篇训练文档
  ├─ 读取 Oracle 选中的候选数 k
  ├─ 独立计算每个候选对参考摘要的 ROUGE-2 precision
  ├─ 选择前 k 个作为 matched labels
  └─ 保存两套标签和 Jaccard 审计
```

控制变量是：同一候选、同一特征、同一 LR、同一解码器，每篇正例数也相同；只改变标签的生成目标。

结果：完整方法仍领先 `+1.99/+2.25/+2.37` ROUGE，但 Expression F1 差异不显著。跟进诊断又发现 Oracle 正例每篇平均长约 11.10 字，因此应说“正例数不是唯一原因”，不能说“竞争机制造成全部提升”。

## 第三部分：词法和位置拆分（约 1.5 分钟）

展示 `main()` 中五种矩阵：

- `full_reference`：decorated text + Legal14 + Section6；
- `lexical_full_aux`：raw text + Legal14 + Section6；
- `decorated_text_only`：raw text + position marker；
- `lexical_text_only`：raw text；
- `position_marker_only`：只有 position marker。

结果：raw lexical text 已达到 `59.86/40.55/49.20`，position-only 只有 `38.92/15.85/24.64`。因此主要信号来自词汇内容，位置和辅助特征只是小增益。

## 第四部分：预算与候选上限（约 1.5 分钟）

展示 `generate_budget()`：

1. 调用同一个 `select_budget_greedy()`；
2. 同时记录 `cap_hit`、`budget_skip_observed` 和 `terminal_stop`；
3. 三者含义不同，不能混报。

在 `B=450, K=8`：

- 803/942 最终因候选上限停止；
- 139/942 最终因剩余候选都放不下而停止；
- 724/942 在选择过程中至少遇到一次放不下的候选。

放宽到 K=10、12 或不限会让输出更长，但 ROUGE 和 Expression F1 下降。因此 K=8 是当前冻结评分器上的有效约束，但不能推广成普遍最优值。

## 第五部分：drop-only 解码对照（约 1.5 分钟）

展示 `generate_drop_only()`：

- 先取得旧解码器选择的八个候选；
- 如果总长度超预算，从尾部删除完整候选；
- 不允许后续候选替补。

这把“避免句内截断”和“允许后续候选继续竞争”区分开。完整 fit/skip 比 drop-only 高 `+1.05/+1.20/+1.51` ROUGE 和 `+3.32` Expression F1。

准确表述：结果支持替代候选继续参与选择的重要性，同时完整方法消除了 379 次句内硬截断。不能声称已经完成两个因素的可加和贡献分解。

## 第六部分：统计检验（约 1 分钟）

展示 `paired_test()` 和 `holm()`：

- 每篇开发文档构成一对；
- 报告平均差；
- 10,000 次文档 bootstrap 得到 95% CI；
- Pratt-Wilcoxon 处理大量零差；
- 同一比较的四项指标使用 Holm 校正。

没有 SENDE 的版本一致逐文档输出，因此不报告 SENDE 配对显著性。

## 第七部分：跟进诊断（约 1 分钟）

在 `run_followup_diagnostics.py` 中：

- `label_diagnostics()` 解释标签的长度和段落偏好；
- `length_close()` 表明 25 字接近子集仍有较小 ROUGE 优势，但 10 字子集不可靠；
- `expression_by_type()` 表明总体指标会掩盖日期、金额等低频类型。

强调：这些是开发集稳健性诊断，不是新的测试排名，也不是法律事实正确性的人工评估。

## 20 秒结尾

补充实验支持三个较稳健的结论：Oracle 优势不只来自正例数量；主要预测信号是词汇内容；完整预算感知选择优于只删除而不替补。它没有解决新颖性、主表基线版本统一和法律事实人工评价，这三项仍需在论文中单独处理。

## 可能被追问的问题

**为什么 25 字子集显著，10 字子集不显著？**  
10 字子集只有 177 篇，且效应更小；这说明长度可能解释相当一部分差距，不能把 25 字结果当作完全去混杂。

**Expression F1 为什么总体几乎不变，但分类型差别很大？**  
类型支持度和平均方式不同。法律、裁判结果高频，金额和日期低频；固定类型并集宏平均还会受到空类型处理影响，因此必须同时报告分类型结果。

**K=8 是不是在开发集调出来的？**  
当前分析只能说明它对冻结评分器有效。敏感性网格是解释既有设置，不用于回改冻结测试协议，也不证明重新训练时仍最优。

**完整性指什么？**  
只指输出不在候选句内部截断，即候选边界完整性，不代表事实、语义或裁判结果完整。
